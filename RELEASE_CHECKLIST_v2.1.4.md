# v2.1.4 Release Validation Checklist

Use this checklist before promoting v2.1.4 from `feature/v2.1.4-course-operations` to the production release branch.

## 1. Upgrade / migration validation

- [ ] Back up the database using the normal `portalctl` upgrade workflow.
- [ ] Deploy the latest `feature/v2.1.4-course-operations` commit using the safe explicit-ref workflow.
- [ ] Run `./portalctl upgrade` successfully.
- [ ] Confirm migrations apply in order:
  - [ ] `0040_v214_show_courses`
  - [ ] `0041_v214_horse_eligibility_override`
  - [ ] `0042_v214_show_horse_list_documents`
- [ ] Run `./portalctl git-status` and confirm the expected commit/ref.
- [ ] Run `./portalctl ps` and confirm all services are healthy.
- [ ] Confirm no unexpected migration is generated by `python manage.py makemigrations --check --dry-run` when run inside the app environment.

## 2. Administrator / Coach validation

### Course Operations
- [ ] Open Coach/Admin dashboard and confirm the next-show Course Information summary appears.
- [ ] Open a show and navigate to **Course Information**.
- [ ] Add a course with type, ring, selected classes, walk time, designer, and notes.
- [ ] Upload a JPG/PNG/WEBP/HEIC or PDF course file.
- [ ] Confirm unsupported file types are rejected.
- [ ] Confirm files over 20 MB are rejected.
- [ ] Confirm **Private Coach/Admin notes** are visible to Coach/Admin.
- [ ] Confirm the uploaded course file opens through the protected portal route.
- [ ] Edit and remove a test course successfully.

### Horse eligibility
- [ ] Assign an eligible registry horse to an eligible class without an override.
- [ ] Attempt an ineligible class assignment and confirm it is rejected without an override.
- [ ] Use the Coach/Admin eligibility override with a reason and confirm the assignment is saved and visibly flagged.
- [ ] Confirm override reason is retained when editing the assignment.

### Hoofprint / Show Horse List
- [ ] Upload a phone photo of a printed Show Horse List.
- [ ] Upload a PDF as a second revision and confirm revision history is retained.
- [ ] Add an internal note and a **Coach Notes for Riders & Parents** note.
- [ ] Confirm internal notes are not shown to Rider/Parent accounts.
- [ ] Confirm the family-visible note is shown to Rider/Parent accounts.
- [ ] Confirm uploaded horse-list files open through the protected authenticated route.
- [ ] Finalize a Hoofprint and confirm a versioned snapshot is created.
- [ ] Change the live horse plan and confirm the portal reports that live data differs from the latest finalized Hoofprint.
- [ ] Confirm completeness warnings appear for missing classes/descriptions/Coggins as appropriate.
- [ ] Confirm warnings do not prevent intentional finalization.

### Horse of the Day history
- [ ] Record a Horse of the Day award.
- [ ] Attempt to remove that horse's show assignment.
- [ ] Confirm deletion is blocked and historical award data remains intact.
- [ ] Confirm marking the horse unavailable remains available as the appropriate operational alternative.

## 3. Assigned Show Lead validation

- [ ] Show Lead dashboard opens and links to Show Day, Horse Readiness, Show Horses, Hoofprint, and Course Information.
- [ ] Assigned Show Lead can open Course Information for the assigned show.
- [ ] Assigned Show Lead can upload/replace course media and external link.
- [ ] Assigned Show Lead cannot edit full course details or private Coach/Admin notes.
- [ ] Assigned Show Lead can upload a Show Horse List revision.
- [ ] Assigned Show Lead can manage show-specific horses/readiness within existing v2.1.3 permissions.
- [ ] Assigned Show Lead cannot edit permanent Horse Registry/Coggins/season eligibility.
- [ ] Show Lead assigned to another show receives 403 for unrelated Course Operations.

## 4. Rider / Parent validation

- [ ] Rider/Parent cannot open Course Operations or protected course documents.
- [ ] Rider/Parent can open the authenticated Show Horse List / Hoofprint area for their team.
- [ ] **My Show Day** shows the latest Show Horse List and family-visible coach notes for participating riders.
- [ ] Internal horse-list notes remain hidden.
- [ ] Existing rider/parent Show Day, schedule, updates, volunteer assignments, and result views still work.

## 5. Show Day regression validation

- [ ] Show Day renders with no planning items.
- [ ] Show Day renders with an item assigned directly to the logged-in user.
- [ ] Show Day renders with an item claimed by the logged-in user.
- [ ] No `owner_id`/planning-item 500 error occurs.
- [ ] Rider check-in/status update still works.
- [ ] Schedule/result links still render for authorized roles.
- [ ] Course board appears for operational users without exposing private coach notes.

## 6. Error / privacy validation

- [ ] Production 403 page renders with `DEBUG=False`.
- [ ] Production 404 page renders with `DEBUG=False`.
- [ ] Production 500 page renders with `DEBUG=False` using a controlled test only.
- [ ] Course files cannot be opened by unauthorized same-team users.
- [ ] Horse-list files cannot be opened by users from another team.
- [ ] Course private notes never appear in Show Lead/Rider/Parent HTML.
- [ ] No raw protected course-file URL is rendered by Course Information.

## 7. Presentation validation

Check desktop and phone-sized layouts in both light and dark modes:

- [ ] Coach/Admin dashboard Course Information card.
- [ ] Show Lead dashboard.
- [ ] Show Detail actions.
- [ ] Show Day course board.
- [ ] Course Information workspace.
- [ ] Course add/edit/media forms.
- [ ] Show Horses eligibility override presentation.
- [ ] Hoofprint Builder change/completeness warnings.
- [ ] Show Horse List upload/revision presentation.
- [ ] My Show Day horse-list/coach-note presentation.
- [ ] 403 / 404 / 500 pages.

## 8. Release documentation

- [ ] `VERSION` is `2.1.4`.
- [ ] `RELEASE_NOTES.md` accurately describes the final release behavior.
- [ ] `ROADMAP.md` reflects 2.1.4 completion and the next 2.1.5 / 2.5.x / 2.9.x / 3.x direction.
- [ ] No unfinished experimental files or accidental debug output remain.
- [ ] Review branch diff against `feature/v2.1.3-show-readiness` before promotion.

## Known deferred cleanup

The temporary `ShowPlanningItem.owner_id` compatibility extension remains intentionally narrow and regression-tested for v2.1.4. Its architectural removal should be handled during the planned 2.9.x cleanup rather than risking a late release regression in the oversized legacy Show Day module.
